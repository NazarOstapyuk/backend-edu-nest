# Резервні копії бази даних

## Налаштування

1. Встановіть Google Drive або OneDrive для ПК і створіть у синхронізованій папці теку, наприклад `G:\Мій диск\edu-backups`.
2. У файлі `.env` бекенду додайте рядок `BACKUP_DIR=G:\Мій диск\edu-backups` (шлях до цієї теки).
3. Якщо Postgres працює не в контейнері `edu_postgres`, додайте `BACKUP_PG_CONTAINER=<назва контейнера>`; для Postgres, встановленого без Docker, — `BACKUP_PG_CONTAINER=` (порожньо), тоді потрібні `pg_dump` і `pg_restore` у `PATH`.
4. Перезапустіть бекенд. На сторінці «Резервні копії» натисніть «Зробити копію зараз» і переконайтеся, що файл з'явився в теці.

Копії робляться щодня о 02:00 за Києвом, поки бекенд запущений. Зберігаються останні 30 щоденних копій і по одній за кожен з останніх 12 місяців; ручні копії — 30 днів; копії «перед відновленням» не видаляються автоматично.

## Відновлення

1. Зупиніть бекенд (Ctrl+C у вікні, де він запущений).
2. Переконайтеся, що Docker і контейнер з базою запущені (`docker compose up -d`).
3. У теці бекенду виконайте `npm run backup:restore -- edu_db_2026-10-13_020000.dump`. Якщо вказати лише назву файлу, він береться з `BACKUP_DIR`; шлях використовується як є. `BACKUP_DIR` має бути заданий у `.env`: туди скрипт зберігає копію поточного стану.
4. Введіть назву бази даних для підтвердження. Скрипт спершу зробить копію поточного стану (`…_pre-restore.dump`), потім відновить вибрану.
5. Виконайте `npx prisma migrate deploy`, щоб оновити структуру бази до поточної версії програми.
6. Запустіть бекенд.

Якщо відновлення не вдалося, поточний стан лишається в копії `…_pre-restore.dump`, її можна відновити тією ж командою.

## Новий комп'ютер

1. Встановіть Docker Desktop, Node 22 і клієнт хмари; дочекайтеся синхронізації теки з копіями.
2. Склонуйте бекенд, створіть `.env`, виконайте `npm ci` і `docker compose up -d`.
3. Відновіть останню копію (розділ «Відновлення»): Після відновлення виконайте `npx prisma migrate deploy`.
4. Запустіть бекенд.
